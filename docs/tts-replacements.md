# 听书替换规则

在「听书 → 替换规则」管理规则。页面标题为「规则」，右侧提供搜索与三点菜单，菜单含新增、预览、排序；顶栏布局沿用音源页的形式。列表支持分组折叠、整组启停、单条编辑/启停/删除和上移/下移，名称升降序会使用原版比较公式更新实际执行顺序。所有音源共用一份规则。保存后，正在进行的朗读从当前原文段落重新准备，旧计划和预取音频失效，暂停状态保持不变。音源切换不会复制或清空规则。

新增/编辑使用对话框，依次为名称、查找内容、替换内容、分组、测试内容、测试输出，正则和启用勾选并排放置。分组可以输入，也能选已有分组；空分组保存为本地化「默认分组」，其他文本不 trim，同名规则可以并存，新增追加到规则列表末尾。保存按原版检查非空名称、非空查找内容及正则可编译性，不执行匹配。「测试」仅运行当前草稿，即使该规则被禁用也可以测试；不混入其他规则，不做结构识别，空查找内容原样返回。三点菜单的「预览」执行所有已启用的已保存规则，展示两阶段结果。两种测试都不保存草稿、不播放音频、不改变听书进度。加载设置、打开规则页和保存规则不执行正则匹配；执行错误在显式测试或实际朗读时显示具体规则。

搜索与原版一致：按 `Character.isWhitespace` 去首尾空白，合并 `\\s+`，去掉英文冒号后的空白，再按空格拆分，各条件之间为 AND。普通关键词匹配名称、查找内容或替换内容，不匹配分组。支持 `source:`、`target:`、`isregex:`、`ischecked:`，例如 `source:重庆 isregex:true ischecked:true`。文本与条件按默认 Locale 转小写后比较，不执行搜索正则。布尔值只有 `true` 视为真；其他值包括空值均为假。`source:`/`target:` 空值匹配对应字段非空的规则。未知前缀按去掉第一个冒号后的普通关键词处理，没有 `name:`/`group:` 语法。

## MultiTTS 1.8.3 对照

基线为 MultiTTS 1.8.3(84) arm64 APK，SHA-256：
`d3f7736b1bf162829677c0772a344696f8f5940e99f45879aa5e26070d0416af`。

| 行为 | 原版依据 | 内置实现 |
| --- | --- | --- |

| 字面顺序 | `p096n6.a.a` | 同阶段一次扫描原输入，最早位置优先，同位置取列表在前的规则；替换结果不再参与本阶段字面扫描，空查找跳过 |
| 正则顺序 | `N6.a.a/b` | 同阶段全部字面替换后，按列表顺序串行执行正则 |
| 捕获组 | `Pattern.matcher(...).replaceAll(target)` | 数字组、命名组、未参与匹配的可选组、反斜杠转义及零宽匹配；保留捕获内容的原文位置 |

| 普通调用点 | 从原 DEX 恢复的 `R6.p.b`，先 `d(segment)`，再 `N6.a.a`，最后统一 backend 合成 | 结构和人物线索固定后纠音，实际选中的单音源和所有已接入后端共用此计划 |

## 原文定位与执行

两阶段传递 UTF-16 输出单元对应的原文码点范围。字面新增内容指向被替换范围，捕获组复制自身映射，零宽插入指向邻接原文码点；中间结果完全清空后再插入时，沿用被清空输入的原文范围。播放时间戳、估算跟随、高亮和失败段落均消费同一计划。捕获重排和变长替换可能使多个合成段共享原文范围，因此续听记录同时保留处理配置及段落序号；规则、文本设置、语言环境或后端上限改变时，按原文位置重新定位。

播放与规则页整体预览使用同一文本设置，按入口过滤、NFC/trim、全段替换、结构/语言分段、普通替换/表情、软句长与后端硬上限依次处理。分段后统一过滤不可朗读内容，避免在多个分段步骤重复过滤。`[[...]]` 独立为 `lang:mark` 段，不改变引号状态、不参与前后文人物判断，也不被普通替换或表情处理改写；控制指令执行与不朗读标记的调度由 #813 接入。

删除后没有可朗读内容的段落不发送合成请求；整章被删除时继续下一章。正则任务复用现有隔离 worker、身份票据、载荷限制、超时和取消回收，不开放脚本或网络桥接。Android 的 ICU 正则将 CharSequence 转为字符串，不能仅依靠字符读取检查中断；进程终止是设备上的实际兜底。命名捕获先解析为编号，避免依赖 API 26 才公开的 `Matcher.start(String)`。

## 兼容差异与后续边界

- 原版非法正则会被自动禁用并写日志；按 #782 的完成标准，内置版终止本次预览或朗读并显示具体条目，规则数据不被悄悄修改。耗时过长规则也报告条目并终止。
- #807 接入原版五状态引号识别、连续对话、上下文传递、NFC、表情与语言候选。引号处理没有通用嵌套栈，换行不重置状态。上下文按书隔离，预取只推进下一章的输入快照；逐段选声、角色规则、语言分配仍由各自后续任务接入。
- NextVol 以章节构建计划，保留所有变换的原文映射；原版按外部合成请求处理。句长遵循软目标并独立执行后端硬上限，同时按 #807 要求保护标记和 UTF-16 代理对，不复制原版硬截断可能拆开代理对的行为。
- Android ICU 与 JDK Pattern 的边界行为由实际平台决定。例如 JDK 空正则会在补充平面字符的两个 UTF-16 单元之间插入；映射始终指向完整原文码点，但不改写平台正则的匹配结果。

本轮还通过 REA 直接核对执行链：`N6.a.c` 的阶段归类（`ev_b5fffe93e731ebcefcc5e070fdc53159e425a0f5d41b7f698005ae4670e690ca`），`N6.a.b/a` 的全段/普通阶段（`ev_b7347c4a792c29ffda891a4a09744df12eec0048f4782db4f10256c8b29e552d`、`ev_a60c7427468b5a62d82526607d312867b9bfbd8658ad7080479f90c8c8999a17`），`n6.a.a` 的一次字面扫描（`ev_e1f9faac5614d825c1e7a3c0c535d2e4c907a5ce75d739a1ad39437ab2511380`）。`TTSService.onSynthesizeText` 在入口规范化后调用全段替换（`ev_98296d9d0cdd037dc33286afa557c48d027da42bce11739a062ac196440c211b`）；`R6.p.b` 的 smali 显示先 `d(segment)` 再普通替换、后端合成（`ev_e8e2986bb6ef97a2b8033e0251c1758208a65ac34dee6ac4fd71e0c2a5e33e02`），该方法 Java 反编译失败，因此使用完整 smali 证据而非缺失的 Java 方法体。原 DEX 的历史恢复与 JVM 重放继续作为补充。
