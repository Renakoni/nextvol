# 听书替换规则

在「听书 → 替换规则」新增、编辑、启停、分组和调整顺序。所有音源共用一份规则。保存后，正在进行的朗读从当前原文段落重新准备，旧计划和预取音频失效，暂停状态保持不变。音源切换不会复制或清空规则。

「执行预览」使用已保存规则及当前编辑草稿，仅生成文本结果，不保存草稿、不播放音频、不改变听书进度。加载设置、打开规则页和保存规则不执行正则；错误在显式预览或实际朗读时显示具体规则。

## MultiTTS 1.8.3 对照

基线为 MultiTTS 1.8.3(84) arm64 APK，SHA-256：
`d3f7736b1bf162829677c0772a344696f8f5940e99f45879aa5e26070d0416af`。

| 行为 | 原版依据 | 内置实现 |
| --- | --- | --- |
| 规则字段 | `org/nobody/multitts/tts/replace/ReplaceRule` | 保留 group、name、source、target、regex、activate；另有本地稳定 id 用于编辑和错误定位 |
| 自动选择阶段 | `N6.a.c` | source 或 target 含任意 `:："“”「」[]\|` 字符则全段替换，否则普通替换；检查原始字符串，包括正则语法字符 |
| 分组 | `ReplaceRule`、`N6.a.c` | group 仅用于整理，不筛选人物、语言或音源 |
| 字面顺序 | `p096n6.a.a` | 同阶段一次扫描原输入，最早位置优先，同位置取列表在前的规则；替换结果不再参与本阶段字面扫描，空查找跳过 |
| 正则顺序 | `N6.a.a/b` | 同阶段全部字面替换后，按列表顺序串行执行正则 |
| 捕获组 | `Pattern.matcher(...).replaceAll(target)` | 数字组、命名组、未参与匹配的可选组、反斜杠转义及零宽匹配；保留捕获内容的原文位置 |
| 全段调用点 | `TTSService`、`G6.b` 调用 `N6.a.b` | 在结构识别之前执行 |
| 普通调用点 | 从原 DEX 恢复的 `R6.p.b`，先 `d(segment)`，再 `N6.a.a`，最后统一 backend 合成 | 结构和人物线索固定后纠音，实际选中的单音源和所有已接入后端共用此计划 |

没有新增按人物或语言筛选替换规则的配置；原版 `ReplaceRule` 没有这些字段。配置文件的导入、导出和迁移由 #789 负责。

原字面算法的 JVM 重放结果如下。正则样例同时使用 JDK 22 `Pattern` 对照；这些重放不代表已经在原 Android 应用上运行。

| 输入 | 规则 | 输出 |
| --- | --- | --- |
| 甲乙 | 字面：甲→乙、乙→丙 | 乙丙 |
| ab | 字面：ab→X、a→Y | X |
| ab | 字面：a→Y、ab→X | Yb |
| 甲 | 列表中先正则 `(乙)→$1丙`，后字面 `甲→乙` | 乙丙 |
| 甲乙 | 正则 `(甲)(乙)→$2-$1-$0` | 乙-甲-甲乙 |
| 乙 | 正则 `(甲)?乙→$1丙` | 丙 |
| 张三 | 正则 `(?<person>张三)→${person}先生` | 张三先生 |
| 😀甲 | 正则 `(😀)(甲)→$2$1` | 甲😀 |
| 甲 | 正则 `(?=甲)→乙` | 乙甲 |

两阶段示例：全段字面规则 `「→“<<张三>>`、`」→”`，普通字面规则 `重庆→崇庆`。原文 `「重庆」` 先变为 `“<<张三>>重庆”`，结构识别保留人物「张三」，合成输入为 `“崇庆”`，定位仍是原文的 `「重庆」`。单独 `甲→<<张三>>` 没有结构触发字符，按原版属于普通阶段，不能逆向改变本次人物识别结果。

## 原文定位与执行

两阶段传递 UTF-16 输出单元对应的原文码点范围。字面新增内容指向被替换范围，捕获组复制自身映射，零宽插入指向邻接原文码点；中间结果完全清空后再插入时，沿用被清空输入的原文范围。播放时间戳、估算跟随、高亮和失败段落均消费同一计划。捕获重排和变长替换可能使多个合成段共享原文范围，因此续听记录同时保留规则版本及段落序号；版本不符时回退到原文位置，旧记录仍可读取。

删除后没有可朗读内容的段落不发送合成请求；整章被删除时继续下一章。正则任务复用现有隔离 worker、身份票据、载荷限制、超时和取消回收，不开放脚本或网络桥接。Android 的 ICU 正则将 CharSequence 转为字符串，不能仅依靠字符读取检查中断；进程终止是设备上的实际兜底。命名捕获先解析为编号，避免依赖 API 26 才公开的 `Matcher.start(String)`。

## 兼容差异与后续边界

- 原版非法正则会被自动禁用并写日志；按 #782 的完成标准，内置版终止本次预览或朗读并显示具体条目，规则数据不被悄悄修改。耗时过长规则也报告条目并终止。
- 本项提供 ASCII 双引号／中文双引号的基础结构边界及 `<<人物>>` 线索，仍使用当前选中的单音源。嵌套／跨段对话、上下文、NFC 及其他预处理、表情等由 #807 补齐；逐段选声、角色规则、语言分配由各自后续任务接入。没有将这些能力标记为已完成。
- 原版在调用全段规则前对外部请求做 NFC 和 trim；当前 NextVol 保留章节原文并在自身计划中处理，尚不宣称外部请求分块及全部预处理已一致。
- Android ICU 与 JDK Pattern 的边界行为由实际平台决定。例如 JDK 空正则会在补充平面字符的两个 UTF-16 单元之间插入；映射始终指向完整原文码点，但不改写平台正则的匹配结果。

REA 核对了 APK 成员身份（`ev_907a7f72061f9bac595eec3a364b7788c386c023a4c85d2e94f75f51d5baf353`、`ev_e90b7f425b215712e008e10b088ae06f520304c9c2a3293e4812cef0c256a546`）。本机 REA Android provider 缺少 `REA_JADX_MCP_JAR`；代码语义来自已提供的反编译文件和现有 JADX 对原 DEX 的单类恢复，没有安装工具或修改 REA 配置。
